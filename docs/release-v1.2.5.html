The upper-bound inventory is a large feature set, even though the workflow defaults to a patch bump. v1.2.4 has one changelog bullet about conversation context. The full range to current main changes 341 files, adds 45,472 lines, removes 4,075 lines, and adds 14 numbered migrations from 158 through 171. 04How the pin and workflow fit

The current release workflow assumes that the release pin is the tip of main. It rejects other refs, collects changes through HEAD, creates the release commit there, and pushes HEAD:main. That is safe only after the team has chosen the current main tip as the pin.

.github/workflows/release-cut.yml:44-54 · main-only guard .github/workflows/release-cut.yml:112-202 · tag-to-HEAD collection .github/workflows/release-cut.yml:389-391 · main and tag push

if [[ "$GITHUB_REF" != "refs/heads/main" ]]; then
  exit 1
fi

range="${LATEST_TAG}..HEAD"
git commit -m "chore: release ${TAG}"
git tag -a "$TAG" -m "$TAG"
git push --atomic origin HEAD:main "refs/tags/$TAG"

This means an older ancestor cannot be selected by changing a field in the existing workflow. If the team chooses an ancestor while newer commits remain on main, the workflow needs an explicit pin/ref design first. Do not reset or force-push main as a workaround.
